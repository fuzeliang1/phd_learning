## 第 7 课：非线性系统和求解器

### 7.1 单摆模型

方向一余量扫描实验用的单摆，是强化学习里常用的 Gym Pendulum-v1 模型。它描述一根均匀细杆，一端固定在转轴上，电机在转轴处施加力矩。

**物理来源**：细杆质量 m、长度 l，绕端点的转动惯量是 m·l²/3；重力作用在杆的中点，产生的力矩是 m·g·(l/2)·sin θ。由"角加速度 = 合力矩 ÷ 转动惯量"：

> θ̈ = [m·g·(l/2)·sin θ + u] ÷ (m·l²/3) = (3g/2l)·sin θ + 3u/(m·l²)

取 m = l = 1、g = 10，得到 θ̈ = 15·sin θ + 3u。

**离散化**（每步 0.05 秒；先更新角速度，再用新的角速度更新角度，叫半隐式欧拉法）：

> ω⁺ = ω + (15·sin θ + 3·u) × 0.05
> θ⁺ = θ + ω⁺ × 0.05

符号含义：
- θ 是角度，θ = 0 表示竖直朝上，θ = π（180°）表示竖直朝下；
- ω 是角速度；
- u 是电机力矩，限制在 |u| ≤ 2。
- 15·sin θ 是重力的作用：摆偏离竖直越多，重力把它往下拽得越狠；3·u 是电机的作用。

**数例**：摆偏了 θ = 0.1 rad（约 5.7°），静止（ω = 0）。
- 不出力（u = 0）：ω⁺ = 15 × sin(0.1) × 0.05 = 0.0749，θ⁺ = 0.1 + 0.0749 × 0.05 = **0.104**。倒得更远了。竖直朝上本身不稳定，和第 1 课的 x⁺ = 2x 一样。
- 用最大力往回拉（u = −2）：ω⁺ = (1.497 − 6) × 0.05 = −0.225，θ⁺ = 0.1 − 0.0113 = **0.089**。拉回来了。

**为什么必须"来回摆几下"**：重力项最大是 15（θ = 90° 时），电机项最大只有 3 × 2 = 6。要把摆静止地撑在某个角度，需要 3|u| ≥ 15|sin θ|，也就是 |sin θ| ≤ 6/15 = 0.4，偏离竖直不超过 **23.6°**。偏得再多，电机就撑不住了，只能像荡秋千一样：先来回摆、积攒能量，再一口气摆上去。这叫**起摆**（swing-up）。

### 7.2 什么叫"非线性"，为什么麻烦

第一部分的模型 x⁺ = 2x + u 是**线性**的：状态翻倍，下一步的结果就翻倍；两个输入的效果可以相加。单摆里有 sin θ，sin(2θ) ≠ 2·sin θ，这就是**非线性**。

LQR 之所以能用，是因为它假设模型是线性的。对单摆，常用的做法是在竖直附近把 sin θ 近似成 θ，叫**线性化**。近似是否成立，取决于角度大小：

| θ | sin θ（真实） | θ（线性近似） | 近似好不好 |
|---|---|---|---|
| 0.1 rad（5.7°） | 0.0998 | 0.1 | 几乎一样 |
| 1.571 rad（90°） | 1.0 | 1.571 | 差 57% |
| 3.142 rad（180°，朝下） | 0 | 3.142 | 完全错 |

所以基于线性化的 LQR 只在竖直附近可靠。余量扫描实验里，认证椭圆（LQR 能保证的安全区）只覆盖竖直附近约 ±9°，原因就在这里。

### 7.3 非线性 MPC：优化问题变难了

MPC 的做法不变：往前预测 N 步、求最优、只执行第一步。但预测用的是带 sin θ 的真实模型，这叫**非线性 MPC（NMPC）**。

第 5 课说过，线性模型加二次代价时，MPC 每步要解的是二次规划（QP）。QP 有一个很好的性质：它是**凸的**，像一个碗，只有一个最低点，从哪里出发往下走都能找到它。

NMPC 要解的是一般的**非线性规划**，通常**不是凸的**，像一片有好几个山谷的地形。

常用的求解器（比如实验里用的 IPOPT）是"牛顿法"一类的方法：从一个起点出发，沿着下坡方向一步步走，走到哪个谷底就停在哪个谷底。这叫**局部求解器**。它找到的是起点附近的最低点（**局部最优**），不一定是全场最低点（**全局最优**）。求解器的起点叫**初值**或**初始猜测**。

### 7.4 数例：起点决定结果

看一个一维函数：f(z) = (z² − 1)² + 0.3z。它有两个山谷：

| 山谷 | 位置 | 高度 |
|---|---|---|
| 左边（全局最优） | z ≈ −1.036 | −0.305 |
| 右边（局部最优） | z ≈ 0.960 | 0.294 |

用最简单的"沿下坡走"（梯度下降：每次 z ← z − 0.01 × 斜率）：
- **从 z = 0.5 出发**：斜率 f′(0.5) = 4 × 0.5 × (0.25 − 1) + 0.3 = −1.2，负的，说明往右是下坡。第一步走到 0.5 + 0.012 = 0.512，一直往右，最后停在 **0.960**，高度 0.294。这是比较差的那个谷。
- **从 z = −0.5 出发**：斜率 f′(−0.5) = +1.8，往左是下坡，最后停在 **−1.036**，高度 −0.305。这是最好的谷。

同一个问题、同一个方法，只因为起点不同，结果就差了一大截。

### 7.5 回到单摆：实验里的发现

单摆起摆问题里的"山谷"，对应不同的摆法：先往左摆还是先往右摆，摆一次还是两次。往前看的步数越多，可选的摆法越多，山谷也越多。

余量扫描实验比较了两种初值（84 个起点，往前看 40 步也就是 2 秒）：
- **好初值**：用一个近乎最优的策略（在值迭代表上做贪心）先走一遍，把这条轨迹当作初值；
- **朴素初值**：假设"摆停在原地、不出力"。

| 往前看 40 步（2 秒） | 好初值 | 朴素初值 |
|---|---|---|
| 能算出合法计划的起点比例 | 96% | 70% |
| 能算出时，比最优多花 | 几乎 0 | 平均 47% |

往前看 60 步、80 步时，朴素初值的情况类似：只覆盖 76%、81%，平均多花 78%、51%，最差的起点代价是最优的 4.4–5.9 倍。

**具体例子**（往前看 40 步）：
- 从 θ = −120°、ω = −2 出发：好初值的总代价 79.2，朴素初值 143.6，多了 81%。求解器陷进了"多摆一圈"的谷。
- 从 θ = −90°、静止出发：好初值能找到起摆方案（总代价 89.7），朴素初值根本找不到合法计划。

只看 10–20 步时，两种初值的结果一样，因为短时域问题的山谷少。

### 7.6 本课要点

非线性 MPC 的结果不仅取决于模型和代价，还取决于求解器从哪里出发。"好的出发点"往往要靠别的知识来提供，比如一个学出来的策略。这是第 9 课"学习 + MPC"的一个重要动机。

## 第 8 课：强化学习里的价值函数

### 8.1 强化学习在做什么

强化学习（Reinforcement Learning，RL）要解决的其实就是第 2 课的最优控制问题：找让总代价最低的控制方法。RL 里习惯说"让总奖励最高"，奖励就是负的代价，只差一个负号。

不同在于做法：
- **控制的做法**：先有模型（公式），再用数学推出最优控制（LQR、MPC）；
- **RL 的做法**：让智能体在环境里反复尝试，从"做了什么、得到了什么"的数据里学出好的控制方法，不一定需要模型的公式。

RL 里有两个核心部件，它们和前面学的概念一一对应：

| RL 的叫法 | 是什么 | 前面课程里的对应 |
|---|---|---|
| actor（策略，policy） | 一个函数：给状态，输出控制量 | 控制律，比如 u = −1.618x |
| critic（价值网络） | 一个函数：给状态，输出"从这里出发还要花多少"的估计 | 价值函数 J(x) |

critic 通常是一个神经网络，从数据里学出来，所以只是 J\* 的**近似**。

### 8.2 折扣因子

RL 里通常给未来的代价打折：第 k 步的代价乘上 γᵏ，γ（读作"gamma"）一般取 0.99。

**数例**：每步代价都是 1，一直持续下去。
- 不打折：1 + 1 + 1 + … = 无穷大；
- 打折（γ = 0.99）：1 + 0.99 + 0.99² + … = 1 ÷ (1 − 0.99) = **100**。

所以 γ = 0.99 大致相当于"只关心未来 100 步左右"。打折让数学上更好处理（无穷和一定收敛），但也意味着 RL 的 critic 和 MPC 理论里不打折的 J 不是同一个量。方向一将来用 RL 的 critic 时，要做换算，这是一个需要注意的技术细节。

### 8.3 critic 是怎么学的：TD 误差

critic 的学习靠的就是第 3 课的 Bellman 方程。拿到一条数据"在状态 x、用了控制 u、付了代价 g、到了 x⁺"，计算：

> **TD 误差** δ = g + J(x⁺) − J(x)

意思是"走了一步之后的估计"（这一步实际付的 g，加上从新状态起的估计）减去"走之前的估计"。TD 是 temporal difference（时间差分）的缩写。

- 如果 J 就是 J\*、u 就是最优控制，Bellman 方程告诉我们 δ = 0。
- δ 不等于 0，说明 J 还不准。训练就朝着让 δ 变小的方向调整网络。

**数例**：假设当前的 critic 是 J(x) = 2x²（太乐观，真实是 4.236x²）。拿到一条数据：x = 1，u = −1.618，付了代价 g = 1 + 2.618 = 3.618，到了 x⁺ = 0.382。
- δ = 3.618 + 2 × 0.382² − 2 × 1² = 3.618 + 0.292 − 2 = **1.91**；
- δ > 0 说明 J(1) 估低了，训练会把 J(1) 往上调。

如果 J 是一张表（每个状态存一个数），最简单的更新是 J(x) ← J(x) + 学习率 × δ。例如学习率 0.1：J(1) 从 2 变成 2 + 0.1 × 1.91 = 2.191，朝真实值 4.236 前进了一点。反复这样更新，表就会逼近真实的价值函数。神经网络的更新原理相同，只是改的是网络参数。

**和方向一的联系**：方向一的终端检验是 TJ(x_N) − J(x_N) ≤ (1 − α)·g。其中 TJ − J 就是"在所有可能的 u 里取最小的 TD 误差"（因为 TJ 是对 u 取最小的"走一步之后的估计"）。所以终端检验本质上是：**用模型在计划终点算一次 TD 误差，误差太大就不信这个 critic**。

例：J = 2x² 在 x = 1 处，TJ − J = 3.667 − 2 = 1.667（第 3.5 节），就是这个最小 TD 误差。它比上面用 u = −1.618 算出的 1.91 小，因为 1.667 是对所有 u 取了最小。

### 8.4 学出来的价值为什么会错

神经网络只在见过的数据附近学得准。没见过的地方，它的输出基本是"猜"出来的，叫**外推**。

**数例**：如果训练数据只来自 |x| ≤ 0.3 的状态，网络在 x = 0.45 处的输出就没有任何数据约束，可能偏得很离谱。方向一玩具例子里的单元 C 就模拟了这种情况：它在 0.45 处估计 J = 0.026，真实值 0.858。

更糟的是，MPC 是一个优化器，**会主动去找价值最低的地方**。估错的低值就像一个陷阱，正好把 MPC 吸过去。玩具例子的结果：
- 从 x = 0.2 出发，轨迹 0.2 → 0.215 → 0.22 → 0.225 → 0.225 → ……卡住不动；
- 原因：在 0.225 处，MPC 每次都计划"这一步取 u = −0.225 原地不动，下一步取 u = 0 跳到 0.45 的坑里"，预测值只有 0.178，看起来最低；但只执行第一步"原地不动"，下一时刻又做同样的计划；
- 每步白付 0.101 的代价，40 步共花 **4.22**，而最优只要 **0.169**。

这在 RL 里叫"价值高估"（对奖励说"高估"，对代价说"低估"，是同一回事）。2025 年的 TD-M(PC)² 论文报告过，TD-MPC 类方法里这种高估是持续存在的（只读到了摘要）。

### 8.5 RL 常见的应对：悲观

RL 的常见做法是训练好几个 critic，取其中最悲观的那个（对代价取最大，对奖励取最小）。SAC、TD3 这些常用算法里"取两个 critic 的较小值"，就是这个思路（以后讲强化学习算法时会细讲）。这样陷阱不容易出现，但代价是：好的估计也被压低，信息浪费了。

方向一选的是另一条路：**允许乐观地用最好的估计，但每次使用前先检验**。

## 第 9 课：把学来的价值放进 MPC

### 9.1 为什么要结合

MPC 和 RL 各有长短：

| | MPC | RL 的 critic |
|---|---|---|
| 优点 | 用模型精确预测近处，严格处理约束 | 包含"很远的未来"的信息，用起来很快 |
| 缺点 | 只看得到 N 步以内 | 不精确，没有保证 |

自然的结合方式：**MPC 精确规划前 N 步，第 N 步之后的代价交给 critic 估计**，也就是把第 6 课的终端代价 J_f 换成学出来的 J。RL 这边的 TD-MPC、LOOP，控制这边的 AC4MPC，都是这个思路。

### 9.2 一个令人惊喜的性质：价值有点错，控制几乎不错

用一个不太准的价值函数 J 做"往前看一步"的控制，得到的控制效果往往比 J 本身准得多。

**计算方法**（不考虑约束）：
1. 按 J = p·x² 做一步贪心控制：第 3.3 节已经推出 u = −2p/(1 + p)·x，也就是 k = 2p/(1 + p)。
2. 这个控制律的实际总代价，用第 2.5 节的公式 (1 + k²)/(1 − (2 − k)²) 计算。

| 用的价值函数 | J 本身的误差 | k | 实际总代价 | 比最优多花 |
|---|---|---|---|---|
| p = 4.236（就是 J\*） | 0 | 1.618 | 4.2361 | 0 |
| p = 4.333（单元 B） | 高 2.3% | 1.625 | 4.2364 | 0.01% |
| p = 5 | 高 18% | 1.667 | 4.25 | 0.33% |
| p = 2 | 低 53% | 1.333 | 5.0 | 18% |

逐行核对 p = 5 这一行：k = 10/6 = 1.667，闭环系数 2 − 1.667 = 0.333，总代价 (1 + 2.778)/(1 − 0.111) = 3.778/0.889 = 4.25。

价值误差 18%，控制效果只差 0.33%。Bertsekas 对此有一个解释：带终端价值的往前看，相当于在 Bellman 方程上做了一步牛顿迭代，而牛顿法的特点是误差被"平方级"地缩小。

但这有前提：误差要平滑。如果是第 8.4 节那种局部陷阱，MPC 会主动利用它，结果可以差 25 倍。所以学习价值"大多数地方好用、个别地方危险"，这正是需要检验的原因。

### 9.3 原论文 Parallel MPC 在这条链上的位置

原论文（Li 等，IEEE TAC 2026）的贡献：同时用好几个终端价值，每一个叫一个"单元"，各自往前看若干步、并行求解，取预测值最低的那个执行。只要每个单元都诚实（TJ ≤ J），就保证：

> 实际总代价 ≤ 所有单元里最低的预测值

这就是第 6 课的移位论证，只是从一个单元推广到多个。

限制：每个单元都必须离线证明诚实，学出来的价值不行。

复现原论文时还发现：**"取预测最低的"不保证比单独用最好的那个单元更好**。在原论文例 4.1 里，从 (−5, 2.7) 出发，单独用单元 3 的总代价是 59.717，并行取最小反而是 60.163。原因是预测值最低的单元，实际跑出来不一定最好（预测值只是上界）。

### 9.4 方向一在这条链上补的是哪一环

把第二部分和第一部分串起来：

1. 第 6 课：MPC 的保证依赖终端价值诚实。
2. 第 8 课：学出来的价值不保证诚实，而且会在没见过的地方出现陷阱。
3. 第 9.2 节：学出来的价值大多数时候很有用。
4. 原论文：多个诚实的单元可以并行取最小，但不接受学来的单元。

方向一要做的就是：**接受学来的单元，用"终端检验 + 移位候选也检验 + 断裂监测"在运行时逐步恢复第 6 课的那条保证。** 第 8.3 节说过，终端检验本质上就是在计划终点算一次 TD 误差。

### 9.5 余量扫描实验说明了什么（现状）

在开始加学习单元之前，先测了"认证的短时域 MPC 到底差在哪里"（详见 `idea_checks/README.md`）：

- 学习价值能带来的好处主要是**覆盖率**：让短时域在认证 MPC 算不出计划的地方也能用。单摆往前看 10 步时，认证 MPC 只覆盖 7% 的起点；要看 40–60 步才能覆盖 96–100%。而只要能算出计划，认证 MPC 的代价就接近最优。
- 最强的对手是"**长时域认证 MPC + 学来的初值**"：它用第 7 课的好初值解决了非凸问题，本身又有标准保证。在单摆上，长时域也不比短时域贵多少：每次求解 60 步约 3.1 ms，10 步约 2.5 ms。
- 所以方向一的主实验，要换到长时域 MPC 本身很贵（高维、多障碍物、多辆车），或者学习价值带有模型算不出的信息（比如 WAM 对他车意图的估计）的场景。这一点需要和导师讨论。

### 9.6 和车载 WAM 课题的关系

车载 WAM（世界-动作模型）擅长理解场景：路口的语义、他车可能怎么走、任务进展到哪一步了。但它运行慢，也可能"幻觉"。底层的 MPC 快、能处理约束，但只懂物理模型。

方向一提供的接口：WAM 给出"从这里往后大概还要付出多少"的估计，当作 MPC 的候选终端价值；终端检验负责在 WAM 估错时把它挡掉，由认证单元保底。物理模型看不到他车意图，时域再长也算不出这部分信息，这正是 9.5 节说的方向一可能真正有优势的情况。

## 自测题

1. 用 IPOPT 解单摆 NMPC，往前看 60 步，从同一个起点出发，换了一个初值，结果代价差了一倍。这是模型错了吗？
2. 一个 critic 在 x = 0.45 处给出 J = 0.026，模型算出 TJ(0.45) = 0.430。当前这一步的代价是 0.101，α = 0.5。它能通过方向一的终端检验吗？
3. 为什么说"价值函数有 18% 的误差，控制只差 0.33%"，却仍然需要检验？
4. γ = 0.9 时，"每步代价都是 1"的折扣总和是多少？大致相当于关心未来多少步？

## 答案

1. 不是。长时域的起摆问题是非凸的，局部求解器从不同初值出发，会落到不同的"山谷"，也就是不同的摆法（第 7.4–7.5 节）。
2. 不能。TJ − J = 0.430 − 0.026 = 0.404，允许的上限是 (1 − 0.5) × 0.101 = 0.051。0.404 远大于 0.051，不通过。这正是"0.45 处的陷阱"。
3. 那张表里的误差是平滑、处处差不多的。学出来的价值还可能在没见过的地方出现局部陷阱，而 MPC 会主动去找最低值、利用陷阱，结果可以差 25 倍（第 8.4 节和第 9.2 节）。检验挡住的就是这种情况。
4. 1 ÷ (1 − 0.9) = 10，大致相当于只关心未来 10 步左右。
