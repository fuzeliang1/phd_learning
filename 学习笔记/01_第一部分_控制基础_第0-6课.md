## 第 0 课：这些知识怎么串起来

方向一用到的背景知识是一条链：

1. **系统模型**。用数学描述"现在的状态 + 施加的控制 → 下一刻的状态"。没有模型，就没法预测，也就谈不上"往前看"。
2. **最优控制**。光能控制还不够，还要控制得"好"。所以先给好坏定一个分数（代价），再找让总分最低的控制方法。
3. **价值函数和 Bellman 方程**。"从某个状态出发，最少还要花多少"，这个量叫价值函数。整个最优控制、MPC 和强化学习，都围绕它展开。这是整条链最核心的概念。
4. **LQR**。线性系统、二次代价、没有约束时，最优控制有现成的公式解。
5. **MPC**。现实中控制量和状态都有限制（约束），LQR 的公式就不适用了。MPC 的办法是"边走边算"：每一步只往前看几步，解一个优化问题。
6. **MPC 为什么可靠**。只往前看几步，会不会越跑越坏？答案取决于"第 N 步之后的代价怎么估计"（终端代价）和"第 N 步落在哪里"（终端集合、不变集）。方向一的"诚实""检验""下降"全部来自这里。

后面三部分接着往下走：

7. 非线性系统和求解器：单摆为什么怕初值（第二部分）。
8. 强化学习里的价值函数：critic 是什么，为什么会估错（第二部分）。
9. 把学来的价值放进 MPC：原论文和方向一在这条链上的位置（第二部分）。
10. 动手计算和证明（第三部分）。
11. 车辆模型和车辆 MPC（第四部分）。

## 第 1 课：离散时间系统模型

### 1.1 状态和控制

**状态**是"描述系统此刻所需的最少信息"：知道了状态，再知道接下来施加什么控制，就能算出未来会怎样。**控制**是"我们能施加的输入"。

**例子：一辆在直线上行驶的小车。**

- 状态：位置 p（米）和速度 v（米/秒）。只知道位置不够：同样在 10 米处，静止的车和以 20 m/s 冲过来的车是完全不同的情况，下一秒会到哪里也完全不同。
- 控制：加速度 u（m/s²），也就是踩油门或刹车。

### 1.2 离散时间：每隔 Δt 看一次

计算机控制不是连续进行的，而是每隔一小段时间 Δt（比如 0.1 秒）测一次状态、算一次控制、把控制量发出去。所以我们关心的是"每隔 Δt，状态怎么变"。

最简单的近似是"新值 = 旧值 + 变化率 × 时间间隔"（这叫**前向欧拉法**）：
- 位置的变化率是速度：p⁺ = p + Δt·v；
- 速度的变化率是加速度：v⁺ = v + Δt·u。

取 Δt = 0.1：

> p⁺ = p + 0.1·v
> v⁺ = v + 0.1·u

上标 ⁺ 表示"下一个时刻"。

**数例**：现在 p = 1 m，v = 2 m/s，踩刹车 u = −1 m/s²。
- p⁺ = 1 + 0.1 × 2 = 1.2 m
- v⁺ = 2 + 0.1 × (−1) = 1.9 m/s

**写成矩阵**：把状态排成列向量 x = (p, v)ᵀ，上面两个式子就是

> x⁺ = A·x + B·u，其中 A = [[1, 0.1], [0, 1]]，B = [0, 0.1]ᵀ。

逐行核对：第一行 p⁺ = 1·p + 0.1·v + 0·u；第二行 v⁺ = 0·p + 1·v + 0.1·u。和上面一致。你学现代控制时见过的连续时间状态空间方程 ẋ = A_c x + B_c u，离散化之后就是这个样子。

### 1.3 主例子：一个会自己跑掉的系统

为了数字好算，后面主要用一维的例子：

> x⁺ = 2x + u

不加控制（u = 0）时，x 每步翻倍：0.1 → 0.2 → 0.4 → 0.8 → 1.6 → ……越来越大。我们的任务是用控制 u 把 x 拉回 0。

可以把它想成一个"倒立"的东西：不管它，它就会越倒越厉害。第二部分的单摆，竖直朝上时就是这样。

### 1.4 稳定和不稳定

**一维的情况**：x⁺ = a·x（不加控制）。
- |a| < 1：x 每步缩小，最终趋于 0，叫**稳定**。例：a = 0.5，1 → 0.5 → 0.25 → 0.125……
- |a| > 1：x 每步放大，叫**不稳定**。例：a = 2，0.1 → 0.2 → 0.4……
- |a| = 1：不放大也不缩小，叫**临界**。

**多维的情况**：x⁺ = A·x，看矩阵 A 的特征值。所有特征值的绝对值都小于 1，才稳定。

例：小车的 A = [[1, 0.1], [0, 1]]，两个特征值都是 1，是临界情况。直观上：不踩油门也不踩刹车，车以恒定速度一直开下去。速度不变，位置却一直增加（1 → 1.2 → 1.4……），不会回到 0，但也不像 a = 2 那样成倍爆炸。

## 第 2 课：最优控制——给"好坏"打分

### 2.1 阶段代价

把 x 拉回 0 有很多办法，哪个好？先定义每一步的"花费"，叫**阶段代价**：

> g(x, u) = x² + u²

- x² 惩罚"偏离目标"：偏得越远，罚得越多。
- u² 惩罚"用力"：用力越猛，罚得越多（费油、费电、磨损、乘客不舒服）。

用平方有两个原因：
1. 正负偏差都算坏：x = −1 和 x = 1 一样糟。
2. 平方函数光滑，求最小值时可以求导，好算。

### 2.2 权重

实际问题里常写成 g = q·x² + r·u²，q 和 r 是**权重**：
- q 大，表示"更在乎精度"，宁可多用力也要快点回到目标；
- r 大，表示"更在乎省力"，宁可慢一点回去。

多维时写成 g = xᵀQx + uᵀRu，Q 和 R 是权重矩阵。例如小车可以取 Q = diag(1, 0.1)：更在乎位置误差，不太在乎速度误差。

### 2.3 总代价

从起点 x₀ 出发，按某个控制方法一直走下去，把每一步的阶段代价全部加起来，就是这个控制方法的**总代价**。总代价越小越好。

### 2.4 数例：从 x₀ = 1 出发，比较三种控制方法

（这一课先不考虑 |u| ≤ 1 的限制，第 4 课再加。）

**方法甲："一步到位"**，u = −2x。
- 第 1 步：x = 1，u = −2，代价 1² + 2² = 5，下一步 x = 2 × 1 − 2 = 0。
- 之后 x = 0、u = 0，代价为 0。
- 总代价 = **5**。

**方法乙："每步减半"**，u = −1.5x。下一步 x⁺ = 2x − 1.5x = 0.5x，每步减半。
- 每步代价 = x² + (1.5x)² = 3.25·x²。
- x 依次是 1, 0.5, 0.25, 0.125, ……，代价依次是 3.25, 0.8125, 0.2031, ……，每一项是前一项的 1/4（因为 x 减半，x² 变成 1/4）。
- 等比数列求和：3.25 × (1 + 1/4 + 1/16 + ……) = 3.25 ÷ (1 − 1/4) = 3.25 × 4/3 = **13/3 ≈ 4.333**。

**方法丙**：u = −1.618x。下一步 x⁺ = 2x − 1.618x = 0.382x，每步变成原来的 0.382 倍。
- 每步代价 = x² + (1.618x)² = (1 + 2.618)·x² = 3.618·x²。
- 每一项是前一项的 0.382² = 0.1459 倍。
- 总代价 = 3.618 ÷ (1 − 0.1459) = 3.618 ÷ 0.8541 = **4.236**。

三者比较：
- 一步到位太猛，用力的代价太大（光第一步就花了 4）；
- 每步减半比较温和；
- 方法丙最好。它就是这个问题的**最优控制**，第 3、4 课会说明它是怎么算出来的。

### 2.5 一般公式：线性控制律 u = −k·x 的总代价

把上面的算法写成一般形式，后面会反复用到。

- 闭环：x⁺ = 2x − kx = (2 − k)·x，所以第 t 步的状态是 x_t = (2 − k)ᵗ·x₀。
- 每步代价：x_t² + (k·x_t)² = (1 + k²)·x_t²。
- 总代价：(1 + k²)·x₀² × [1 + (2 − k)² + (2 − k)⁴ + ……]。

当 |2 − k| < 1 时，方括号里的等比数列收敛，得到

> 总代价 = (1 + k²) / (1 − (2 − k)²) × x₀²

代入核对：
- k = 2：(1 + 4)/(1 − 0) = 5 ✓
- k = 1.5：3.25/(1 − 0.25) = 4.333 ✓
- k = 1.618：3.618/(1 − 0.1459) = 4.236 ✓

当 |2 − k| ≥ 1 时（比如 k = 0.5，2 − k = 1.5），x 不收敛，总代价是无穷大：这个控制律根本稳不住系统。

对 k 求这个公式的最小值，得到的就是 k = 1.618。也就是说，方法丙是所有"u = −kx"形式的控制里最好的。第 4 课的 LQR 理论还会告诉我们：在没有约束时，它是所有控制方法里最好的。

### 2.6 本课要点

最优不是"最快到达"，而是"偏差和用力之间的最佳平衡"。权重 q、r 决定了这个平衡点。

## 第 3 课：价值函数和 Bellman 方程（最核心的一课）

### 3.1 价值函数

**价值函数** J\*(x) 的定义：从状态 x 出发，用最优的控制方法，总共最少要花多少。

上面的例子算出来 J\*(1) = 4.236。对一般的 x，因为总代价和 x₀² 成正比，J\*(x) = 4.236·x²。

> 例：J\*(0.4) = 4.236 × 0.16 = 0.678，意思是从 0.4 出发，最少要花 0.678。

叫法：强化学习里叫"价值函数"（value function）；控制里也叫"最优代价函数"或"剩余代价"（cost-to-go）。是同一个东西。

### 3.2 Bellman 方程：把"走无穷多步"拆成"走一步 + 剩下的"

关键观察：**最优走法的"剩下部分"，也一定是从新状态出发的最优走法。** 否则，把剩下那段换成更好的走法，整体就会更好，和"最优"矛盾。

**先看一个生活里的例子：从家到学校。**

从家出发有两条路：
- 走路口甲：家到甲 3 km，甲到学校最短 4 km；
- 走路口乙：家到乙 2 km，乙到学校最短 6 km。

记"从某处到学校的最短距离"为 J\*，则 J\*(甲) = 4，J\*(乙) = 6。从家出发的最短距离：

> J\*(家) = 两个选择里取最小 [ 3 + J\*(甲)，2 + J\*(乙) ] = 最小 [ 7, 8 ] = 7

也就是：从这里到终点的最短路 = 走一步的路程 + 从下一站到终点的最短路，再在所有可能的第一步里挑最好的。

**写成控制的语言：**

> J\*(x) = 在所有 u 里取最小 [ 这一步的代价 g(x, u) + 从下一个状态起的最少花费 J\*(x⁺) ]

这叫 **Bellman 方程**，也就是"动态规划"的核心。

**数例：在 x = 1 处验证 J\*(x) = 4.236x² 满足 Bellman 方程。**

右边是：最小化 f(u) = 1 + u² + 4.236·(2 + u)²。

- 求导：f′(u) = 2u + 2 × 4.236 × (2 + u) = 2u + 8.472u + 16.944 = 10.472u + 16.944。
- 令 f′(u) = 0：u = −16.944 / 10.472 = **−1.618**。这正是方法丙的控制量，它就是这样算出来的。
- 代回：下一步 x⁺ = 2 − 1.618 = 0.382，f(−1.618) = 1 + 2.618 + 4.236 × 0.382² = 1 + 2.618 + 0.618 = **4.236**。

右边算出来是 4.236，等于左边 J\*(1)。说明 4.236x² 确实满足 Bellman 方程。

### 3.3 Bellman 算子 T

把 Bellman 方程右边的操作单独起个名字，叫 **T**。给它任意一个"剩余代价的估计" J，它输出一个新的函数：

> (TJ)(x) = 在所有 u 里取最小 [ g(x, u) + J(x⁺) ]

直观意思："**往前试走一步，再用 J 估计剩下的**"。

Bellman 方程于是可以写成 **J\* = T J\***：最优价值函数是 T 的"不动点"，试走一步之后结果不变。

**一个在本例里很好用的公式**：如果 J(x) = p·x²（p 是某个正数），那么

> (TJ)(x) = 在所有 u 里取最小 [ x² + u² + p·(2x + u)² ]

推导：
1. 对 u 求导：2u + 2p·(2x + u) = 0，解得 u = −2p·x / (1 + p)。
2. 这时 2x + u = 2x − 2px/(1 + p) = 2x/(1 + p)。
3. 所以 u² + p·(2x + u)² = 4p²x²/(1 + p)² + 4p·x²/(1 + p)² = 4p(p + 1)·x²/(1 + p)² = 4p·x²/(1 + p)。
4. 加上 x²，得到：

> **T 把 p·x² 变成 [1 + 4p/(1 + p)]·x²**

也就是说，在这个例子里，T 的作用就是"把系数 p 变成 1 + 4p/(1 + p)"。后面所有关于 T 的计算都用这个公式。例：p = 4.236 时，1 + 16.944/5.236 = 4.236，不变，正是不动点。

### 3.4 值迭代：反复用 T，就能逼近 J\*

从一个很粗糙的估计开始，比如 J₀ = 0（"剩下的不花钱"），反复用 T：

> J₁ = T J₀，J₂ = T J₁，J₃ = T J₂，……

用 3.3 节的公式，只需要跟踪系数 p：p_{k+1} = 1 + 4p_k/(1 + p_k)。

| 迭代次数 k | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| p_k | 0 | 1 | 3 | 4 | 4.2 | 4.231 | 4.235 | 4.236 |

逐个核对前几项：p₁ = 1 + 0 = 1；p₂ = 1 + 4/2 = 3；p₃ = 1 + 12/4 = 4；p₄ = 1 + 16/5 = 4.2。

很快就收敛到 4.236。

**第 k 次迭代的含义**：J_k 是"只看 k 步、之后不管"时的最优代价。
- k = 1：只看 1 步，之后不管，那就不用力（u = 0），代价是 x²，所以 p₁ = 1。
- 看得越远，越接近真实的 J\*。

**收敛到哪里**：不动点满足 p = 1 + 4p/(1 + p)。两边乘以 (1 + p)：p + p² = 1 + p + 4p，整理得 p² − 4p − 1 = 0，解得 p = 2 + √5 ≈ 4.236（另一个根是负数，舍去）。最优控制 u = −2p/(1 + p)·x = −8.472/5.236·x = −1.618x。

这一招叫**值迭代**。第二部分的单摆实验里算参考值 J_ref，就是在 300×241 个网格点上做了一百五十多次这样的迭代。

### 3.5 "诚实"的终端价值：TJ ≤ J

这是方向一里反复出现的条件，现在可以说清楚了。

假设有人给你一个"剩余代价的估计" J，怎么判断它靠不靠谱？**往前试走一步看看：比较 TJ 和 J。**

**情况一：J 是某个真实控制方法的代价。** 例如方法乙"每步减半"，J_B(x) = 4.333x²，真的能做到这个代价。
- 用 3.3 节的公式：T J_B 的系数 = 1 + 4 × 4.333/5.333 = 1 + 3.25 = 4.25。
- 4.25 ≤ 4.333，即 **TJ ≤ J**。
- 意思是：试走一步再用 J 估计，结果不比直接用 J 估计差。J 没有夸大"未来很便宜"，是一个**诚实的上界**：真实的最少花费不会超过它。

**情况二：J 估得太乐观。** 例如 J(x) = 2x²（真实是 4.236x²，它说少了一半多）。
- T J 的系数 = 1 + 8/3 = 3.667。
- 3.667 > 2，即 **TJ > J**。
- 意思是：只要试走一步，就发现"说好的 2，实际至少要 3.667"，J 自相矛盾了。

**把几个系数放在一起看**：

| J = p·x² 中的 p | 2 | 4 | 4.236（真实） | 4.333（单元 B） | 5 |
|---|---|---|---|---|---|
| TJ 的系数 | 3.667 | 4.2 | 4.236 | 4.25 | 4.333 |
| TJ ≤ J？ | 否 | 否 | 相等 | 是 | 是 |
| 含义 | 很乐观 | 略乐观 | 精确 | 诚实，略保守 | 诚实，较保守 |

在这个例子里可以证明：TJ ≤ J 成立，当且仅当 p ≥ 4.236。因为 1 + 4p/(1 + p) ≤ p 两边乘以 (1 + p) 后整理成 p² − 4p − 1 ≥ 0。也就是说，诚实的估计恰好是那些"不低于真实值"的估计。

原论文把满足 TJ ≤ J 的函数叫做"在 **L-region** 里"（L 代表 Lyapunov）。**方向一的终端检验，就是在 MPC 计划的终点上做这个"试走一步"的检查。** 第 12 课会看到，方向一把条件放宽了一点，所以略乐观的 J = 4x² 也能通过，而很乐观的估计会被拦下。

## 第 4 课：LQR——没有约束时的标准答案

### 4.1 LQR 是什么

**LQR**（Linear Quadratic Regulator，线性二次调节器）解决的就是前面那类问题：
- 系统是线性的：x⁺ = Ax + Bu；
- 代价是二次的：xᵀQx + uᵀRu；
- **没有约束**。

这类问题有现成的公式解：
- 价值函数一定是二次的：J\*(x) = xᵀPx（一维时是 p·x²）；
- 最优控制一定是线性的：u = −Kx（一维时是 u = −k·x）。

矩阵 P 满足 **Riccati 方程**：

> P = Q + AᵀPA − AᵀPB·(R + BᵀPB)⁻¹·BᵀPA

增益是 K = (R + BᵀPB)⁻¹·BᵀPA。

在一维例子里 A = 2、B = 1、Q = 1、R = 1，Riccati 方程变成 p = 1 + 4p − 4p²/(1 + p)，和第 3.4 节的不动点方程 p = 1 + 4p/(1 + p) 是同一个（因为 4p − 4p²/(1 + p) = 4p/(1 + p)）。解出 p = 2 + √5 ≈ 4.236，k = 2p/(1 + p) ≈ 1.618。

**Riccati 方程其实就是把"J = 二次函数"代进 Bellman 方程 J = TJ 之后的结果。** 第 3 课的值迭代表，就是在一步步解这个方程。

工具：MATLAB 的 `dlqr`，Python 的 `scipy.linalg.solve_discrete_are`，都是在解它。

### 4.2 LQR 的致命局限：约束

现实中控制量是有限的：油门有最大值，电机有最大力矩，方向盘有最大转角。在例子里加一条 **|u| ≤ 1**，看看会发生什么。

**数例一：从 x = 1 出发。**
- LQR 要 u = −1.618，超过了 1。
- 只能"截断"到 u = −1：x⁺ = 2 × 1 − 1 = **1**，原地不动。
- 下一步还是一样……永远停在 1，每步付 1 + 1 = 2 的代价，总代价无穷大。

**数例二：从 x = 1.2 出发。** 最大力也只能把它变成 2.4 − 1 = 1.4，越来越远，彻底失控。

**原因**：x 每步要翻倍，而 |u| ≤ 1 最多只能抵消 1。只有当 2x − 1 < x，也就是 x < 1 时，才有可能把 x 往回拉。所以 |x| ≥ 1 的状态根本救不回来。

**数例三：从 x = 0.8 出发，截断后的 LQR 恰好还能用。**
- 第 1 步：LQR 要 −1.294，截断成 −1，x = 1.6 − 1 = 0.6；
- 第 2 步：LQR 要 −0.971，没超限，x = 1.2 − 0.971 = 0.229；
- 之后 0.0875 → 0.0334 → ……，收敛到 0。

但这只是这个一维例子里的巧合。一般来说：
- 截断后的控制不再是最优的；
- 多维系统里，截断可能让系统失稳；
- LQR 完全不管状态约束（比如 |x| ≤ 2，或者车不能开出车道）。

这说明两件事：
1. 有约束时，"能不能控制回来"本身就成了问题，有些状态根本救不回来；
2. LQR 的公式解不再适用，截断也没有任何保证。

所以需要 MPC。

## 第 5 课：MPC——边走边算，每次只看几步

### 5.1 MPC 的四个步骤

**MPC**（Model Predictive Control，模型预测控制）每个时刻做四件事：

1. 测量当前状态 x；
2. 用模型往前预测 N 步，在**满足所有约束**的前提下，求"N 步阶段代价之和 + 终点的剩余代价估计 J(x_N)"最小的控制序列 u₀, u₁, …, u_{N−1}；
3. **只执行第一步** u₀；
4. 到了下一时刻，回到第 1 步，重新测量、重新计算。

第 2 步是一个优化问题。线性系统加二次代价时，它是**二次规划（QP）**，有很快的求解器。第 10 课会把它完整地写出来并手算一遍。

N 叫**预测时域**（或"时域"），J(x_N) 叫**终端代价**或**终端价值**。

### 5.2 为什么只执行第一步

因为预测总有误差：模型不准，还有扰动（风、路面不平）。每一步重新测量、重新规划，就能不断纠正误差。这是 MPC 能用于真实系统的关键。

这就像开车：眼睛一直看着前方 100 米规划路线，但每一刻只决定当下怎么打方向盘；下一刻看到新情况，再重新规划。计划总是往前看 N 步，每次只执行一步，所以叫**滚动时域**。

### 5.3 数例：N = 1，终端价值用 J_B

在 x = 0.4 处，求解：

> 最小化 f(u) = 0.4² + u² + (13/3)·(0.8 + u)²
> 要求 |u| ≤ 1，并且下一步 |x⁺| ≤ 2/3（第 6 课会解释为什么要求这个）

其中 x⁺ = 2 × 0.4 + u = 0.8 + u。

求解：
1. 求导：f′(u) = 2u + (26/3)·(0.8 + u)。
2. 令其为 0：(2 + 26/3)·u = −(26/3) × 0.8，即 (32/3)·u = −20.8/3，所以 u = −20.8/32 = **−0.65**。
3. 检查约束：|−0.65| ≤ 1 ✓；x⁺ = 0.8 − 0.65 = 0.15，|0.15| ≤ 2/3 ✓。
4. 预测的总代价 = 0.16 + 0.4225 + 4.333 × 0.0225 = 0.16 + 0.4225 + 0.0975 = **0.680**。

对比真实最优 J\*(0.4) = 4.236 × 0.16 = **0.678**。这里可以直接用无约束的结果，是因为从 0.4 出发，LQR 第一步只要 |u| = 0.647 ≤ 1，之后越来越小，约束从来不起作用。

只往前看 1 步，靠一个好的终端价值，就几乎做到了最优。方向一的余量扫描实验发现的也是这件事："认证的 MPC 只要能用，就接近最优。"

## 第 6 课：MPC 为什么不会越跑越坏

这一课是方向一里"诚实""检验""下降""断裂"这些词的来源，请慢慢看。

### 6.1 先看一个反例：短视的 MPC

如果 N = 1，而且终端价值设为 0（"下一步之后就不管了"）：

- x = 0.4：最小化 0.16 + u² + 0，显然 u = 0 最省（这一步不用力就不花钱）。于是 x⁺ = 0.8。
- x = 0.8：同样选 u = 0，x⁺ = 1.6。
- x = 1.6：选 u = 0，x⁺ = 3.2，超出了 |x| ≤ 2 的允许范围，而且第 4 课说过，|x| ≥ 1 之后就再也救不回来了。

每一步都"省了眼前的力气"，结果把系统送进了救不回来的区域。**问题出在 MPC 看不到第 N 步之后的后果。**

### 6.2 解决办法：终端代价 + 终端集合

两样东西配合使用：

**终端代价 J_f**：给第 N 步之后的代价一个估计，让 MPC"知道未来还要花钱"。

**终端集合 X_f**：要求第 N 步的终点必须落在一个"安全区"里。安全区的含义是：在这个区域里，有一个已知的控制方法，能让状态一直留在区域里，并且不违反任何约束。

**例子**：X_f = {|x| ≤ 2/3}，已知的控制方法是"每步减半" u = −1.5x。
- 在区域里，|u| = 1.5|x| ≤ 1.5 × 2/3 = 1，不违反约束 |u| ≤ 1；
- 下一步 x⁺ = 0.5x，绝对值更小，还在区域里；
- 区域里 |x| ≤ 2/3 < 2，也不违反 |x| ≤ 2。

这种"进去了就出不来、而且在里面一直合法"的区域，叫**不变集**。5.3 节里"下一步 |x⁺| ≤ 2/3"的要求，就是终端集合约束。原论文里单元 B 的设计就是这个：J_B = (13/3)·x² 加上 |x| ≤ 2/3。

### 6.3 MPC 稳定性的三个标准条件

教材里证明 MPC 稳定，通常要求终端代价 J_f、终端集合 X_f 和一个"局部控制律" κ（这里是 u = −1.5x）满足三个条件：

1. **局部控制律在终端集合里合法**：对 X_f 里的每一个 x，κ(x) 满足控制约束，x 本身满足状态约束。
2. **终端集合是不变集**：x 在 X_f 里，下一步 f(x, κ(x)) 也在 X_f 里。
3. **终端代价满足下降条件**：对 X_f 里的每一个 x，J_f(f(x, κ(x))) + g(x, κ(x)) ≤ J_f(x)。

用单元 B 逐条核对：
1. |x| ≤ 2/3 时 |u| = 1.5|x| ≤ 1 ✓。
2. x⁺ = 0.5x，仍在 |x| ≤ 2/3 内 ✓。
3. J_B(0.5x) + 3.25x² = (13/3) × 0.25x² + 3.25x² = 1.0833x² + 3.25x² = 4.333x² = J_B(x)，恰好相等，满足"≤" ✓。

第 3 条和第 3.5 节的"诚实"是一回事：试走一步（这里用 κ 走），代价不比原来的估计高。

### 6.4 移位论证：为什么代价一定会下降

这是整个 MPC 稳定性理论的核心论证，只有三步。继续用 5.3 节的例子。

**第一步：昨天的计划，今天还能用。**

昨天在 x = 0.4 算出的计划是"先用 u = −0.65 走到 0.15，之后交给每步减半"。今天到了 0.15，把昨天计划的第一步去掉，剩下的部分（从 0.15 开始每步减半）仍然是一个合法的计划：每步减半在 |x| ≤ 2/3 里永远合法（6.3 节条件 1、2）。这个"旧计划去掉第一步"叫**移位候选**。

**第二步：这个旧计划的代价可以算出来。**

旧计划的代价 = 昨天的预测值 − 昨天已经付掉的那一步：
- 昨天预测 0.680，已付 0.16 + 0.4225 = 0.5825；
- 剩下 0.680 − 0.5825 = **0.0975**。
- 核对：J_B(0.15) = 4.333 × 0.0225 = 0.0975，正好相等。

**第三步：今天重新优化，只会更好。**

今天在 0.15 重新求解：最小化 0.0225 + u² + (13/3)·(0.3 + u)²。
- 求导：2u + (26/3)·(0.3 + u) = 0，解得 u = −2.6/(32/3) = −0.24375，下一步 x = 0.05625。
- 最优值 = 0.0225 + 0.0594 + 4.333 × 0.003164 = 0.0225 + 0.0594 + 0.0137 = **0.0956**。
- 0.0956 不超过 0.0975。这是必然的，因为旧计划只是今天众多选项之一，最优解不可能比它差。

所以：**今天的预测值 ≤ 昨天的预测值 − 昨天付的阶段代价**，即 0.0956 ≤ 0.680 − 0.5825。

### 6.5 这个下降说明了什么

预测值每走一步至少减少"这一步付的代价"，而它又不可能小于 0。把每一步的下降加起来：

> 所有步的代价加起来 ≤ 一开始的预测值

数例：从 0.4 出发，这个 MPC 的总代价 ≤ 0.680。

可以把预测值想成一笔"存款"：每走一步，至少要从存款里扣掉这一步的花费；存款不能变成负数；所以总花费不会超过最初的存款。控制理论里把这种只降不升、而且不小于 0 的量叫 **Lyapunov 函数**，它保证系统稳定：花费有限，状态就必然趋于 0。

### 6.6 和方向一的对应

| 本课的概念 | 方向一里的对应 |
|---|---|
| 终端代价满足 TJ ≤ J（诚实） | 认证单元离线证明诚实；学习单元在计划终点现场检验 |
| 移位候选 | 方向一第 3 步：上一步的计划也算候选，也要检验 |
| 预测值每步下降 | 断裂监测：如果某一步没降够，就判定"证书断了" |
| 总代价 ≤ 初始预测值 | 定理 1：总代价 ≤ v₀/α（α 是放宽的系数，允许只降"一部分"，第 12 课） |

关键在于：第三步"今天只会更好"依赖第二步"旧计划的代价算得出来"，而第二步依赖终端代价**诚实**（6.3 节第 3 条）。如果终端价值是学出来的、不诚实，第二步就不成立，整个保证就塌了。这就是方向一要在线检验的根本原因。

## 自测题

1. 系统 x⁺ = 0.5x + u 不加控制会怎样？x⁺ = 3x + u 呢？
2. 有人给出终端价值 J(x) = 5x²。在我们的例子里 TJ = 4.333x²。它诚实吗？
3. 第 6.1 节的短视 MPC，如果改成终端价值 J_B = 4.333x² 再试一次，从 x = 0.4 出发，第一步会选什么？
4. 用第 3.3 节的公式判断：J(x) = 4.5x² 诚实吗？
5. 第 6.4 节第三步说"今天的最优值不可能比旧计划差"，这句话依赖什么前提？

## 答案

1. 系数 0.5 的绝对值小于 1，x 会自己衰减到 0，是稳定的。系数 3 大于 1，x 每步变成 3 倍，不稳定。
2. 诚实。TJ = 4.333x² ≤ 5x²，试走一步不比原来的估计差。它偏保守（真实值是 4.236x²），但不会骗人。
3. 就是第 5.3 节的结果：u = −0.65，下一步到 0.15。有了终端价值，MPC 知道"拖着不管，将来要付更多"，所以现在就出力。
4. TJ 的系数 = 1 + 4 × 4.5/5.5 = 1 + 3.273 = 4.273 ≤ 4.5，诚实（p = 4.5 ≥ 4.236，符合 3.5 节的结论）。
5. 依赖"旧计划今天仍然合法"，也就是终端集合是不变集、局部控制律在里面不违反约束（6.3 节条件 1、2）。如果旧计划今天不合法，它就不是候选，比较就无从谈起。
